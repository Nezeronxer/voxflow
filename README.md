# VoxFlow 2.0 — бесплатная диктовка для macOS и Windows

VoxFlow превращает речь в готовый текст в активном приложении: чате, браузере,
документе или IDE. Локальное распознавание работает без подписки и API-ключа;
облачные STT/rewrite-провайдеры подключаются только пользователем в режиме BYOK.

## Установка на Mac

Нужен Mac с чипом Apple (M1 и новее) и macOS 11 или новее.

**Способ 1 - одна команда (рекомендуется).** Откройте «Терминал» (Программы →
Утилиты → Терминал), вставьте строку и нажмите Return:

```sh
curl -fsSL https://raw.githubusercontent.com/Nezeronxer/voxflow/master/script/install-macos.sh | bash
```

Программа скачается из последнего релиза, сверится по контрольной сумме, встанет
в «Программы» и запустится. Никаких предупреждений macOS не будет. Эта же
команда потом обновляет VoxFlow; если уже стоит последняя версия, она просто
откроет программу. Ваши настройки и модели не трогаются.

**Способ 2 - файл .dmg.** Скачайте `VoxFlow-macOS-<версия>-arm64-<метка>.dmg` со
страницы [релизов](https://github.com/Nezeronxer/voxflow/releases/latest), откройте и
перетащите VoxFlow в «Программы». При первом запуске macOS может сказать, что не
может проверить программу. Тогда один раз: «Системные настройки → Конфиденциальность
и безопасность» → внизу кнопка «Всё равно открыть».

### Доступы

VoxFlow просит три доступа: микрофон, «Универсальный доступ» (вставка текста) и
«Мониторинг ввода» (клавиша диктовки). Их выдают один раз, и они остаются после
обновлений. После обновления до 2.3.2 доступы попросят в последний раз.

## Что нового в 2.1

- Встроенный локальный ИИ: приложение само скачивает llama.cpp и модели
  Qwen3 / Qwen2.5 / Gemma 3 с проверкой контрольных сумм и правит текст после
  распознавания без облака и без установки Ollama.
- Настройка графического ускорения (авто / вкл / выкл) для локальной модели ИИ.
- Постобработка больше не вырезает обычные слова («нет», «погоди», «короче»),
  а режим «авто» не подставляет английский перевод вместо русской речи.
- Новый интерфейс: пульт диктовки с индикатором уровня, светлая и тёмная темы.

## Что нового в 2.0

- Полностью новый адаптивный интерфейс: главный экран, компактная навигация,
  вложенные настройки и отдельный Flow Bar для диктовки.
- Контекст активного приложения и профили для чатов, почты, документов, кода и
  AI-промптов.
- Hold-to-talk и toggle-режимы с исправленным поведением короткого нажатия,
  отмены через `Esc` и смены хоткея/режима во время удержания.
- Две пользовательские физические клавиши — для диктовки и улучшения выделенного
  текста — с проверкой конфликтов и применением без перезапуска.
- Flow Bar свободно перетаскивается между экранами, запоминает позицию и меняет
  размер от 75% до 150% в основных настройках.
- Личный словарь, сниппеты, история, статистика, изученные исправления,
  smart formatting и опциональный rewrite.
- Локальные маршруты: GigaAM v3 для русского, Parakeet TDT v3 для английского,
  «авто» — GigaAM, а английскую фразу берёт Parakeet.
- Возобновляемые загрузки моделей и проверка SHA-256 до установки.
- Локальный fallback сохраняет выбранный маршрут GigaAM/Parakeet, даже
  если облачный провайдер временно недоступен.
- Секреты больше не возвращаются в интерфейс: UI видит только статус ключа и
  поддерживает явное удаление.
- Раздельные release-контуры: macOS ARM64 и Windows x64, platform-safe updater,
  version gate и автоматические frontend/Rust проверки.

## Платформы

| Платформа | Цель релиза 2.0 | Артефакт |
|---|---|---|
| macOS Apple Silicon | macOS 11+, ARM64 | `VoxFlow-macOS-<версия>-arm64-signed-unnotarized.dmg` |
| Windows | Windows 10/11, x64 | `VoxFlow-Setup-2.0.9.exe` |
| Linux | x64, glibc 2.38+ | `VoxFlow-<версия>-linux-x64.AppImage`, `.deb`, `.rpm`, `.pkg.tar.zst` (Arch) |

Windows-установщик работает per-user и не требует отдельной установки VC++
Redistributable с повышением прав: нужные Microsoft VC++ CRT/OpenMP DLL лежат
рядом с приложением. Microsoft-signed Evergreen WebView2
bootstrapper встроен в setup и запускается без показа окна только тогда, когда
WebView2 Runtime не найден; в этом редком случае установщику нужен интернет.
Это не означает, что сам `VoxFlow-Setup-*.exe` подписан — текущий CI выпускает
unsigned setup, пока владелец не предоставит Authenticode-сертификат.

macOS: релизы подписаны постоянным самоподписанным ключом (без нотаризации),
поэтому доступы выдаются один раз. Linux: deb/rpm/AppImage собираются на
ubuntu-24.04, нужен glibc 2.38+ (Ubuntu 24.04+, Debian 13+, Fedora 39+, Arch).

### Arch Linux, Manjaro, EndeavourOS

Пакет для pacman лежит в каждом релизе. Поставить последнюю версию одной командой
(скачивает пакет, сверяет SHA-256 с `SHA256SUMS-linux.txt`, ставит через `pacman -U`):

```sh
cd /tmp && tag=$(curl -fsSL https://api.github.com/repos/Nezeronxer/voxflow/releases/latest | sed -n 's/.*"tag_name": *"\(v[^"]*\)".*/\1/p') && v=${tag#v} && curl -fLO "https://github.com/Nezeronxer/voxflow/releases/download/$tag/VoxFlow-$v-linux-x64.pkg.tar.zst" -fLO "https://github.com/Nezeronxer/voxflow/releases/download/$tag/SHA256SUMS-linux.txt" && sha256sum --check --ignore-missing SHA256SUMS-linux.txt && sudo pacman -U "VoxFlow-$v-linux-x64.pkg.tar.zst"
```

Дальше обновления ставит само приложение: скачивает новый `.pkg.tar.zst`, сверяет
SHA-256 и запускает `pkexec pacman -U` (система спросит пароль). Если в системе нет
агента polkit (например, голый Hyprland), VoxFlow покажет команду `sudo pacman -U …`
для терминала. Удалить: `sudo pacman -R voxflow`.

Intel Mac не входит в подтверждённую матрицу 2.0: текущий ONNX Runtime для
GigaAM/Parakeet не предоставляет используемый проектом macOS x86_64 runtime.

## Как пользоваться

1. Установите VoxFlow и выдайте доступ к микрофону. На macOS также нужны Input
   Monitoring для глобального Right Option и Accessibility для вставки текста.
2. Поставьте курсор в нужное поле.
3. Удерживайте выбранную клавишу (на macOS по умолчанию правый `Option`,
   на Windows — правый `Control`) либо используйте toggle-режим.
4. Говорите: Flow Bar показывает запись и обработку, после чего текст попадает
   в активное окно.

Flow Bar можно перетащить за любую точку плашки. Размер меняется в «Настройки →
Основные → Вид» кнопками, ползунком или сбрасывается к 100%.

Для русского выберите «Русский» (GigaAM), для английского — «English» (Parakeet).
«Авто» распознаёт GigaAM, а английскую фразу — Parakeet. Локальный режим не требует
аккаунта; cloud STT и rewrite остаются опциональными BYOK-функциями.

## Настройки

- **Основные** — микрофон, клавиши диктовки/улучшения, размер Flow Bar,
  hold/toggle, включённая по умолчанию защёлка быстрым двойным тапом, языки,
  автозапуск и auto-mute.
- **Диктовка** — пунктуация, слова-паразиты, voice commands, форматирование и
  способ безопасной вставки.
- **Модели** — движок, язык, каталог локальных моделей, скорость и потоки CPU.
- **Персонализация** — словарь, сниппеты, исправления и rewrite-профили.
- **Приложения** — правила для активного приложения и проверка текущего контекста.
- **Приватность** — локальный/BYOK режим и управление сохранёнными ключами.
- **Дополнительно** — диагностика и обновления.

## Приватность

- Локальный режим не отправляет аудио или текст внешним STT-сервисам.
- Сохранение обучающих пар «аудио ↔ текст» на новых установках выключено до
  явного согласия пользователя и управляется отдельным переключателем.
- После успешной вставки VoxFlow ненадолго принимает только сигнал о факте
  обычного ручного редактирования, затем перечитывает то же поле через системный
  UI Automation / Accessibility и локально сохраняет лишь безопасную связанную
  замену. Нажатые символы и буфер обмена глобально не записываются; парольные
  поля, смена окна и похожие на секреты значения исключаются.
- API-ключи маскируются и не совершают обратный путь из backend в React state.
- Пользовательские данные хранятся в локальном каталоге приложения; на Unix
  чувствительные каталоги/файлы получают ограниченные permissions.
- BYOK-запросы выполняются только после настройки соответствующего провайдера.

## Автоматическая проверка

Frontend:

```bash
cd voxflow
npm ci
npm test
npm run build
npm audit --audit-level=high
```

Rust:

```bash
cargo fmt --manifest-path voxflow/src-tauri/Cargo.toml --all -- --check
cargo clippy --locked --manifest-path voxflow/src-tauri/Cargo.toml --all-targets -- -D warnings
cargo test --locked --manifest-path voxflow/src-tauri/Cargo.toml --lib
python3 script/check_versions.py --tag v2.0.9
```

`.github/workflows/ci.yml` повторяет проверки на Windows x64 и macOS ARM64.
Tag-release запускает `.github/workflows/release.yml`: он вызывает Windows-
сборщик `.github/workflows/build-installer.yml` и macOS ARM64-сборщик
`.github/workflows/release-macos-arm64.yml`. Отдельные сборщики можно запускать
вручную для QA-артефактов; GitHub Release они не публикуют. Оркестратор
публикует общий release только после проверки обоих платформенных
пакетов и их SHA-256.

Некоторые model/audio E2E-тесты намеренно opt-in: им нужны локальные веса,
приватные голосовые WAV-файлы или сетевой провайдер. Они не заменяются
синтетическим «успехом» в обычном CI.

## Подпись релизов

Релизы macOS подписываются постоянным самоподписанным сертификатом
`VoxFlow Self-Signed` (режим `signed-unnotarized`, ассеты
`VoxFlow-macOS-<версия>-arm64-signed-unnotarized.dmg`). Его требование подписи
(identifier + certificate leaf) одинаково во всех сборках, поэтому выданные
доступы не слетают при обновлении. Нотаризации нет: при установке из .dmg macOS
один раз попросит «Всё равно открыть», установка командой этого не требует.
Ключ создаёт `script/setup-macos-signing.sh`, он хранится в секретах репозитория
`MACOS_SELF_SIGNED_P12_BASE64` и `MACOS_SELF_SIGNED_P12_PASSWORD`.

Без этих секретов workflow возвращается к ad-hoc подписи (`-adhoc.dmg`) и проверяет
`codesign --verify --deep --strict`; доступы в таком режиме придётся выдавать заново
после каждого обновления. Релизы до 2.3.2 были ad-hoc.

Если в GitHub Actions заданы `APPLE_CERTIFICATE`,
`APPLE_CERTIFICATE_PASSWORD` и один полный набор учётных данных для
notarization, pipeline импортирует Developer ID Application certificate в
одноразовый keychain, подписывает и нотариально заверяет `.app` и `.dmg`.
Доступны либо `APPLE_ID` + app-specific `APPLE_PASSWORD` +
`APPLE_TEAM_ID`, либо `APPLE_API_ISSUER` + `APPLE_API_KEY` +
`APPLE_API_PRIVATE_KEY_BASE64`. Developer ID имеет приоритет над самоподписью и
понадобится, если появится аккаунт Apple. Неполный или смешанный набор секретов
аварийно останавливает release, а все временные keychain/файлы удаляются
перед завершением job. Для Windows по-прежнему нужен Authenticode certificate.
