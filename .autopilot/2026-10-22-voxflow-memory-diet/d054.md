Текст решения D-054 из отчёта таска 02 (для DECISIONS.md, оформить как остальные D-0xx):

Что: в релиз Linux добавлен `VoxFlow-X.Y.Z-linux-x64.pkg.tar.zst`. Его собирает `script/build_arch_package.sh` из готового deb: makepkg по `script/arch/PKGBUILD` в контейнере archlinux:latest от обычного пользователя, с `!strip !debug`. Depends взяты по NEEDED бинарника (libayatana-appindicator - через dlopen для трея). CI проверяет `pacman -Qip`, список файлов и установку в чистом контейнере с ldd. Встроенное обновление считает копию «пакетом Arch», только если нет `APPIMAGE` и `pacman -Qqo <exe>` называет владельцем пакет `voxflow`. Тогда оно берёт `.pkg.tar.zst`, сверяет SHA-256 и ставит через `pkexec /usr/bin/pacman -U --noconfirm`, затем перезапускает приложение. Если pkexec нет, агента polkit нет или пароль не введён, файл сохраняется и показывается команда `sudo pacman -U '<путь>'`. AppImage, deb/rpm, macOS и Windows работают как раньше.

Почему: пользователь выбрал «пакет для pacman в релизе» без AUR, а Tauri 2 не собирает pacman-пакеты. Перекладка готового deb даёт тот же проверенный бинарник, что в deb и AppImage, без второй сборки. Признак «владелец - пакет voxflow» не даёт обновлению трогать установки, сделанные другими способами (debtap, чужой PKGBUILD).

Отвергнуто: AUR (пользователь не выбрал); сборка из исходников в PKGBUILD (второй бинарник и долгий CI); ручной `.PKGINFO` через bsdtar без makepkg (хрупко, нет `.MTREE`/`.BUILDINFO`); признак «дистрибутив Arch по /etc/os-release» (не отличает пакет от AppImage, deb или ручной установки); установка по URL через `pacman -U <url>` в README (для удалённых файлов pacman требует подпись).

Цифры памяти для заметок релиза - в D-053 (таск 01): в работе с полной GigaAM + Parakeet было 2517-2984 МБ, стало ~1950; после выгрузки в простое ~98 МБ (тестовый процесс).
