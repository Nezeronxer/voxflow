## Что должно заработать

Пользователь хочет «суперчёткое» распознавание и на вопрос «что мешает» ответил «не знаю, сделай максимум». Сейчас русский идёт через GigaAM v3 e2e RNNT **int8** (`istupakov/gigaam-v3-onnx`, ревизия в models.rs). В том же репозитории HF есть **fp32**: `v3_e2e_rnnt_encoder.onnx` (885 МБ), `v3_e2e_rnnt_decoder.onnx`, `v3_e2e_rnnt_joint.onnx`, а также `v3_e2e_ctc.onnx`. Замерь на записях этого мака, даёт ли fp32 (и CTC fp32) заметный выигрыш, и прими только доказанное.

Методика D-036 (DECISIONS.md, прочитай раздел целиком): псевдоэталон Whisper large-v3 (`whisper-cli -l ru`, модель `~/Library/Application Support/VoxFlow/models/ggml-large-v3.bin`; бинарник whisper-cli собирается/лежит в ресурсах проекта - найди, не ставь новый), выборка 110 записей из `dataset/` (seed 7: 45 длиннее 25 с, 35 по 8-25 с, 30 по 2-8 с), пословный WER без регистра/ё/пунктуации, инструмент `src/final_eval.rs` тест `final_accuracy_eval` (`#[ignore]`, `VOXFLOW_EVAL_LIST`, `VOXFLOW_EVAL_REF`). Псевдоэталоны и списки клади во временную папку вне репозитория. Уже отвергнуто в D-036: паддинг, порог VAD, длина куска, нормализация - не повторять. Fp32-файлы скачай в отдельную папку (не в боевую `models/gigaam`) с проверкой SHA-256 из HF API (`/api/models/istupakov/gigaam-v3-onnx/tree/<ревизия>` отдаёт lfs.oid).
