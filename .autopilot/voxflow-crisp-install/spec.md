# Спецификация: VoxFlow - чёткое распознавание, простая установка на Mac, релиз

## Задача

Я диктую на маке, а у меня стоит древняя 2.0.16, и распознавание не такое чёткое, как хочется.
Свежие версии на GitHub не вышли: 2.2.0 и 2.2.1 так и остались тегами без релиза. Ставить
VoxFlow на мак неудобно: macOS ругается на «непроверенного разработчика», а после каждого
обновления заново просит доступы (Универсальный доступ, Мониторинг ввода), будто это новая
программа. Хочу, чтобы и мне, и любому человеку ставилось как нормальная программа.

## Решение

- Новая версия **2.3.0** опубликована на GitHub для Windows, macOS и Linux.
- macOS-сборка подписана **постоянным ключом** (самоподпись, без Apple Developer): доступы
  выдаются один раз и переживают все следующие обновления.
- Установка на мак **одной командой** в Терминале: скачивает последний релиз, сверяет
  контрольную сумму, ставит в «Программы», запускает - без предупреждений macOS.
  Для тех, кто ставит из .dmg, в README и в самом .dmg понятная инструкция на один шаг.
- При первом запуске приложение **одним экраном** проводит по доступам: микрофон,
  Универсальный доступ, Мониторинг ввода - с живыми галочками и кнопками «Открыть настройки».
- Распознавание: точный вариант GigaAM (без сжатия int8) и другие рычаги замерены на моих
  записях; в релиз идёт только то, что дало заметный выигрыш.
- На этом маке стоит 2.3.0, поставленная той самой командой, модели скачаны.

## Решения по реализации

1. **Подпись macOS - самоподписанный сертификат подписи кода**, сгенерированный один раз
   на этом маке (`openssl`, EKU codeSigning, срок 10 лет), импортирован в login Keychain и
   выгружен в секреты репозитория скриптом, который значения не печатает. Почему: TCC
   хранит грант по designated requirement; у самоподписи оно `identifier + certificate leaf`,
   стабильное между сборками, а у ad-hoc - cdhash, меняющийся каждую сборку. Apple Developer
   нет (ответ пользователя), нотаризации нет.
2. **Секреты CI - отдельные имена** `MACOS_SELF_SIGNED_P12_BASE64` и
   `MACOS_SELF_SIGNED_P12_PASSWORD`, чтобы не путать с веткой Developer ID (она остаётся
   как есть и имеет приоритет, если появятся ключи Apple). Нет секретов → ad-hoc как раньше.
3. **Имя macOS-ассета** - остаётся в шаблоне, который понимают уже установленные версии
   (иначе их апдейтер не увидит 2.3.0). Точное имя решает таск подписи по коду апдейтера;
   новая версия апдейтера принимает и старое, и новое имя.
4. **Linux-релиз на ubuntu-24.04**, как CI. Почему: предсобранный onnxruntime в `ort`
   rc.12 требует glibc 2.38; на 22.04 (2.35) не линкуется. Linux ещё ни разу не выходил -
   пользователей на старых дистрибутивах нет. Минимальные версии дистрибутивов - в README.
5. **Установщик - `script/install-macos.sh`** в репозитории, запуск через
   `curl -fsSL https://raw.githubusercontent.com/Nezeronxer/voxflow/master/script/install-macos.sh | bash`.
   Последний релиз - через GitHub API без токена, ассет `.dmg` для arm64, сверка с
   `SHA256SUMS` релиза, `hdiutil attach -nobrowse`, `ditto` во временную папку рядом с
   `/Applications`, затем замена; `xattr -dr com.apple.quarantine`; `open`. Без sudo, если
   `/Applications` доступна на запись; иначе - понятная фраза. Почему curl: загрузка curl
   не ставит карантин, Gatekeeper не спрашивает.
6. **Онбординг доступов** - строится на существующем `macos_permissions.rs` и баннере во
   фронте (что именно есть - см. разведку в `interfaces.md`); добавляется явный запрос
   микрофона и живой статус. Новых экранов-мастеров не плодить.
7. **Точность** - замер по `final_eval.rs` (`final_accuracy_eval`), псевдоэталон Whisper
   large-v3, та же выборка-методика, что D-036, 110+ записей. Варианты (рычаги): (а) GigaAM v3 e2e RNNT fp32 против int8 - основной;
   (б) GigaAM v3 e2e CTC fp32; (в) если (а) выиграл - fp32 в живом превью тоже или только в финале.
   Уже отвергнуто в D-036 (паддинг, порог VAD, длина куска, нормализация) - не повторять.
   Методика D-036: псевдоэталон Whisper large-v3 (`whisper-cli -l ru`), 110 записей seed 7
   (45 длиннее 25 с, 35 по 8-25 с, 30 по 2-8 с), пословный WER без регистра/пунктуации. Порог
   принятия - ≥0,5 п.п. и согласованно на коротких и длинных; плюс RTF. Итог - запись D-038.
8. **Версия 2.3.0**, а не перевешивание тега v2.2.1: тег уже запушен, переписывать
   опубликованную историю не нужно; заметки описывают 2.2.0, 2.2.1 и 2.3.0 вместе.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `script/setup-macos-signing.sh` | создание ключа подписи | запуск без аргументов; итог - identity `VoxFlow Self-Signed` в Keychain + 2 секрета в GitHub | openssl, пароль p12 (генерируется, не печатается) |
| `build_macos_arm64_release.sh` + `release-macos-arm64.yml` | подпись и имена ассетов | env `VOXFLOW_SIGNING_IDENTITY`; режимы developer-id / self-signed / adhoc | импорт p12 во временный keychain |
| `updater.rs` | выбор и установка ассета | существующие функции; шаблон имён | - |
| `script/install-macos.sh` | установка для людей | одна команда | всё |
| `macos_permissions.rs` + фронт баннера | доступы | существующие команды + `microphone_status/request` | AVFoundation FFI |
| модели (`models.rs`, `gigaam.rs`) | каталог и загрузка GigaAM | существующие `DirModel` | выбор fp32/int8 |

Швы для тестов: существующие юнит-тесты `updater.rs` (имена ассетов), `models.rs`
(каталог), `final_eval.rs` (замер, `#[ignore]`); shell-скрипты - `bash -n` + shellcheck,
если есть, и прогон установщика на этом маке.
