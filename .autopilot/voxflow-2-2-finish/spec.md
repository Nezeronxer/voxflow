# Спецификация: VoxFlow - доделать 2.2 (релиз 2.2.1)

## Задача

Я выпустил VoxFlow 2.2.0 с поддержкой Linux, а он так и не вышел: тег есть, релиза нет, у
пользователей Windows и macOS обновление не пришло. На своём Arch (Hyprland) я им пользоваться не
могу, потому что его никто не запускал, а плашка на Wayland уходит под окна. Если в режиме живой
печати нажать хоткей, пока прошлая фраза ещё распознаётся, прошлая фраза пропадает целиком.

## Решение

Выходит релиз 2.2.1 для Windows, macOS и Linux. Фраза в режиме живой печати больше не теряется.
Плашка на Wayland-композиторах с layer-shell (Hyprland, Sway, KDE) держится поверх окон и не
забирает фокус. VoxFlow собран и запущен на этой машине, а рабочая папка очищена от мусора
Dropbox.

## Решения по реализации

- **Релиз - v2.2.1 с master** после зелёного CI. Тег v2.2.0 не трогаем (ответ пользователя). Тегаем
  только коммит из master с зелёным CI (грабли 2.0.21).
- **Живая печать: ждать, а не стирать.** На старте нового поколения в always/auto черновик прошлого
  поколения остаётся за её финалом, а превью нового поколения не печатает в поле, пока
  `FinalQueue` не пропустит его ход. Почему так: дифф финала по backspace верен, только пока курсор
  стоит сразу за черновиком. Если не пускать новую печать раньше, курсор цел, и не нужно
  отслеживать позицию. Цена - новая фраза появляется в поле позже, на время финала прошлой
  (обычно 0,2-4 с). Плашка при этом рисует превью сразу.
- **Строгость поколений сохраняется для всего остального.** Ослабляется только условие «финал
  нужен», и только для поколения, вытесненного новым стартом, а не Esc. Это то же различие
  `cancel_floor`, что уже есть для режима «never».
- **Wayland: gtk-layer-shell.** Крейт `gtk-layer-shell` (системная `gtk-layer-shell` уже нужна
  Tauri на многих дистрибутивах; на этой машине стоит 0.10.1). Только `cfg(target_os = "linux")`.
  Слой задаётся до первого `show()`. Почему не правила hyprland.conf: они чинят одну машину и
  один композитор, а пакет едет всем. ASSUMPTION: новая зависимость принята за пользователя.
  Пакетам deb/rpm и README дописать зависимость `gtk-layer-shell` / `libgtk-layer-shell0`.
- **Сборка рантайма в workflow через `bash script/...`.** Тогда флаг исполнения в git ни на что
  не влияет.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `engine` (final queue + поколения) | порядок вставок, судьба черновика | существующие `final_still_wanted`, `FinalQueue::{enter, wait_turn}`; новый вход: ожидание хода перед печатью превью | как черновик передаётся финалу |
| `overlay` (lib.rs `setup_overlay` + новый `linux_overlay`) | окно плашки | `setup_overlay(app)` без изменения сигнатуры | layer-shell, проверку поддержки |
| CI/релиз | workflow, версии | - | - |

Швы для тестов: тесты движка через существующие unit-тесты `engine.rs` (FinalQueue, final_still_wanted)
- тот же шов, что в 2.2.0. Оверлей на layer-shell юнит-тестом не проверяется: проверка - живой
запуск на этой машине (история 13-14).
