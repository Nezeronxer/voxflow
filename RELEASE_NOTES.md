# VoxFlow v2.0.17 — постобработка на любом сервисе и любом ключе, Fn как клавиша диктовки

Релиз поверх 2.0.16. Настройки ИИ перестали быть закрытым списком из четырёх
сервисов, а на диктовку теперь можно назначить Fn (macOS).

## Свой сервис постобработки было некуда вписать

Симптом: в разделе «ИИ» четыре прибитых пресета и ни одного поля с адресом.
Подключить свой сервис или локальный шлюз — негде.

Причина. В самом движке ветка OpenAI-совместимого API умела произвольный
`/chat/completions` с самого начала, наружу это просто не выводилось. Хуже того,
определение провайдера по адресу при незнакомом хосте возвращало первый пресет:
чужой URL молча подписывался «OpenRouter» и уходил в его ветку с бесплатными
моделями.

**Исправление.** Каталог провайдеров вынесен отдельным модулем и показывается
списком: OpenRouter, Groq, OpenAI, DeepSeek, Mistral, Together, Cerebras, xAI,
Gemini в OpenAI-режиме, Anthropic в OpenAI-режиме, Aqua, LM Studio (локально) —
и **«Своё»** со своими Base URL, моделью и заголовком ключа. У каждого пресета
рядом ссылка, где взять ключ. Незнакомый адрес теперь резолвится в «Своё», а не
в первый попавшийся пресет.

Поле модели — текст с подсказками, а не закрытый список: наборы моделей у
провайдеров меняются чаще релизов VoxFlow, и закрытый список означал бы «нужной
модели нет» на ровном месте.

## Ключ уходил только как `Authorization: Bearer`

Сервисы с `x-api-key` не подключались в принципе — имя заголовка было зашито.

**Исправление.** Имя заголовка стало настройкой. Пусто или `Authorization` —
прежнее `Authorization: Bearer {ключ}`, иначе `{заголовок}: {ключ}`. Имя
пропускается через санитайзер: значение с двоеточием, переводом строки или
неположенными символами отбрасывается целиком, а не склеивается в заголовок.
При выборе готового пресета заголовок сбрасывается — оставшийся от «Своего»
ломал бы авторизацию молча.

Список доверенных хостов расширен адресами новых пресетов. Он гейтит **только**
подхват ключа из переменных окружения: чужому хосту env-ключ не отдаём, а ключ,
введённый в настройках, работает с любым адресом. Для режима «Своё» интерфейс
это прямо пишет.

## Fn как клавиша диктовки (macOS)

Fn не знали ни разбор имени клавиши, ни таблица keycode'ов macOS. Теперь знают:
keycode 63 плюс флаг `SecondaryFn` в тапе — без флага нажатие терялось, когда
HID-состояние клавиши пустое, потому что Fn приходит только через `flagsChanged`.

- **Только macOS.** На Windows и Linux Fn обрабатывается прошивкой клавиатуры и
  до системы не доходит; там назначение отклоняется явно, а не притворяется
  рабочим хоткеем.
- **Назначается кнопкой «назначить Fn / 🌐»**, а не нажатием: вебвью не отдаёт
  для Fn ни `keydown`, ни `keyup`, ловить в поле захвата нечего.
- Если Fn в системных настройках переключает язык или открывает эмодзи, система
  откроет свою панель поверх диктовки — об этом сказано в интерфейсе. Тап
  слушающий, чужие клавиши мы не съедаем.

## Мелочи

- Раздел «Модели» показывает путь к папке моделей с кнопкой «открыть» и говорит,
  откуда файлы качаются: huggingface.co, закреплённые ревизии, проверка SHA-256.
- Ссылки из настроек открываются в браузере. Раньше это были `<a target="_blank">`,
  которые в вебвью Tauri не делают ничего — все подсказки со ссылками были мёртвыми.

  env-ключ достаётся только известным и loopback-хостам, незнакомый адрес даёт
