## D-000 · Кодовое имя
**VoxFlow** (оставлено из брифа). Идентификатор приложения: `com.voxflow.app`. Папка приложения: `voxflow/`, governance-доки и git-репозиторий — в корне `wispr flow/`.

## D-001 · Оболочка: Tauri 2 (React 19 + TS + Vite 7)
Скаффолд через `create-tauri-app@4.6.2`, шаблон `react-ts`, `--tauri-version 2`.
Реальные версии на момент сборки (из сгенерированных манифестов):

## D-002 · ASR-движок: whisper.cpp как SIDECAR-бинарь (не FFI/не сборка)
**Решение:** использовать **готовый пребилт** `whisper.cpp v1.8.6` (`whisper-bin-x64.zip`), запускать `whisper-server.exe` как управляемый дочерний процесс (HTTP на `127.0.0.1`, модель грузится один раз) + `whisper-cli.exe` как one-shot fallback.
**Почему:** на машине **нет cmake и clang** → собрать whisper.cpp через `whisper-rs`/`cmake`-крейт нельзя. Пребилт убирает C++-сборку у нас и у пользователя; брифом sidecar разрешён явно. Persistent-server даёт низкую задержку для повторной диктовки (модель не перезагружается).
**Альтернативы отклонены:** `whisper-rs` (нужен cmake), `candle-whisper` (тянет тяжёлый pure-Rust стек, медленный CPU-инференс, долгая сборка), установка cmake (добавляет build-зависимость, всё равно бандлим DLL).
**Ускорение (опц.):** `whisper-cublas-12.4.0-bin-x64.zip` для NVIDIA — переключаемый профиль движка.

## D-003 · Модель по умолчанию: large-v3-turbo Q5_0
**Решение:** дефолт `ggml-large-v3-turbo-q5_0.bin` (574 МБ) — сильный русский, вдвое меньше fp16 (1.62 ГБ). Качалка: `https://huggingface.co/ggerganov/whisper.cpp/resolve/main/<file>`.
- Смоук-тест/быстрый режим: `ggml-base.bin` (148 МБ).
- Максимум качества (опц.): `ggml-large-v3-turbo.bin` (fp16) или `ggml-large-v3.bin`.
**Модель НЕ бандлится в инсталлятор** — качается при первом запуске (выбор пользователя), чтобы установщик был лёгким.

## D-004 · Захват аудио: cpal + pure-Rust ресемпл + VAD
- **cpal** — кроссплатформенный захват с устройства (нативный sample rate/формат).
- **rubato** (pure Rust) — ресемпл в **16 кГц моно f32** (whisper.cpp требует строго 16 кГц).
- **hound** — запись 16-bit PCM WAV для передачи в whisper.
- **VAD** — простой энергетический (RMS + hangover) в чистом Rust, без C-зависимостей. Для hold-to-talk VAD не критичен (запись от нажатия до отпускания); нужен для trim тишины и авто-сегментации (Flow).
**Почему pure-Rust:** избегаем `webrtc-vad`/C-сборок, минимум зависимостей.

## D-005 · Глобальный хоткей / hold-to-talk: rdev
**Решение:** **rdev** (low-level global key listener: `WH_KEYBOARD_LL` на Windows, `CGEventTap` на macOS) как основной движок хоткеев.
**Почему:** `tauri-plugin-global-shortcut` регистрирует акселераторы-комбинации и не умеет hold-to-talk на одиночном модификаторе (нет keyup для bare-модификатора). rdev даёт keydown/keyup для ЛЮБОЙ клавиши → честный hold-to-talk и toggle единым механизмом, pure-Rust.
**Дефолтная клавиша:** **Right Ctrl** (hold-to-talk), настраиваемая. Toggle — отдельная назначаемая комбинация.
**Про Fn:** на Windows Fn обычно обрабатывается прошивкой и не виден ОС (как и предупреждал бриф) → дефолт не на Fn. Если конкретная клавиша перехватывается — даём выбрать в настройках.
**Грабля:** rdev `listen` блокирует поток и не grab'ит по умолчанию → крутим на выделенном потоке, не подавляя клавишу (Right Ctrl сам по себе безвреден для чужих приложений).

## D-006 · Инжект текста: arboard (буфер) + enigo (paste/печать)
**Решение:** основной путь — **clipboard-paste**: сохранить текущий буфер → положить распознанный текст → послать **Ctrl+V** (enigo) → восстановить буфер.
Fallback — **enigo type** (посимвольно), если paste недоступен.
**Почему paste-первым:** надёжно для Юникода/кириллицы и длинного текста, быстрее посимвольной печати.
- **arboard** — кроссплатформенный буфер (save/set/restore), pure-Rust/winapi.
- **enigo** — синтетические нажатия (Ctrl+V и type-fallback), на Windows через winapi (без C-сборки).
**Off-focus:** окно настроек скрыто (работаем из трея), overlay — non-activating (`focus:false`), фокус ОС остаётся на приложении пользователя → Ctrl+V уходит в их окно. На macOS позже добавим AXUIElement для умной вставки.

## D-007 · Хранилище: rusqlite (bundled SQLite)
**Решение:** **rusqlite** с фичей `bundled` (компилит `sqlite3.c` через `cc`-крейт; cc сам находит MSVC через vswhere, cmake не нужен).
**Почему:** одна C-единица трансляции, надёжно; даёт SQL для словаря/сниппетов/истории/статистики/настроек (бриф требует SQLite).
**План B (если cc-сборка sqlite сломается):** настройки/словарь в JSON-файлах (serde) до починки. Проверяется сборкой.

## D-008 · LLM-постобработка: rule-based по умолчанию, LLM опционально
**Решение:** дефолт — **детерминированный rule-based** очиститель (паразиты, капитализация, авто-пунктуация-добивка) в Rust, полностью офлайн и быстрый. Опционально — LLM (локальный **Ollama** если запущен, либо облако Claude/OpenAI BYOK) для тона/Command Mode.
**Почему:** whisper для русского уже расставляет пунктуацию прилично; тяжёлый LLM не обязателен для рабочего среза и противоречил бы анти-оверинжинирингу. **Verbatim-режим** = полностью выключенная постобработка.

## D-009 · Структура процессов и окон
- **Трей** — основная точка (tauri tray icon), окно настроек открывается из трея, по умолчанию скрыто.
- **Overlay** — маленькое non-activating окно-индикатор записи (`focus:false`, `skipTaskbar:true`, `alwaysOnTop:true`).
- **Sidecar whisper-server** — управляемый дочерний процесс, поднимается при старте/первой диктовке, гасится при выходе.

## D-010 · Автозапуск — только с явного согласия
`tauri-plugin-autostart`, по умолчанию ВЫКЛ, включается тумблером в настройках (бриф: автозапуск только с явного согласия).

## D-011 · Загрузка моделей — системный curl, не reqwest
**Решение:** качать модели через `curl.exe` (есть в Windows 10+), прогресс — поллингом размера `.part`-файла; событие `model:progress/done/error`.
**Почему (вскрыто при сборке):** `reqwest 0.13` тянет `hyper-rustls → rustls → aws-lc-rs → aws-lc-sys`, а `aws-lc-sys` требует **cmake/nasm** (которых нет). curl использует системный SChannel — ноль C-сборок, и заодно убирает тяжёлый async-стек (reqwest+tokio+futures-util удалены).
**Альтернатива отклонена:** `reqwest` с `rustls`/`native-tls` — всё равно вытягивал aws-lc через platform-verifier.

## D-012 · rusqlite пин на 0.32 (libsqlite3-sys 0.30)
**Решение:** `rusqlite = "0.32"` (тянет `libsqlite3-sys 0.30.1`).
**Почему (вскрыто при сборке):** `rusqlite 0.40` → `libsqlite3-sys 0.38`, чей `build.rs` использует нестабильный макрос `cfg_select!` → E0658 на stable `rustc 1.93.1`. Версия 0.30 его не использует. API (`Connection`, `params!`, `query_map`, `execute_batch`) полностью совместим.

## D-013 · Запускать ТОЛЬКО продакшен-бинарь от `tauri build` (не `cargo build`)
**Грабля (вскрыто в рантайме):** голый `cargo build --release` в Tauri 2 даёт бинарь, который **остаётся в dev-режиме** и грузит фронтенд с дев-сервера `http://localhost:1420`. Без запущенного Vite WebView2 показывает страницу-ошибку Edge → выглядит как «открылся браузер». Подтверждено `netstat`: `SYN_SENT → 127.0.0.1:1420`.
**Правило:** для запуска/демо/раздачи использовать бинарь из **`tauri build`** (он же в инсталляторе) — фронтенд вшит в .exe, localhost не дёргается (проверено netstat: к 1420 обращений нет). Для разработки — `npm run tauri dev` (он сам поднимает Vite). `cargo build` использовать только для `cargo check`/линковки, НЕ для запуска GUI.

## D-014 · GPU-ускорение (cuBLAS) + persistent whisper-server
**Контекст:** у пользователя RTX 4060 Ti (16 ГБ), i5-12400F, 32 ГБ. Замеры (фраза ~9с):
- CPU fp16 large, `whisper-cli` one-shot: **~15с** (≈1.6× реального времени) — неюзабельно.
- CPU fp16 large, `whisper-server` (модель в RAM): тоже **~15с** — узкое место не загрузка, а вычисления.
- **GPU (cuBLAS) + `whisper-server`:** прогрев ~2с (разово), горячий запрос **0.36с** (≈25× realtime). ✅
**Решения:**
- Брать **cuBLAS-сборку** whisper.cpp v1.8.6 (`whisper-cublas-12.4.0-bin-x64.zip`) — она самодостаточна: внутри `cudart64_12`, `cublas64_12`, `cublasLt64_12`, `ggml-cuda`, `nvrtc` (нужен только драйвер NVIDIA). Положена в `resources/whisper-cuda/Release/` (урезана до 12 файлов).
- `paths::whisper_dir` отдаёт приоритет CUDA-сборке при наличии NVIDIA (детект: `System32\nvcuda.dll`), иначе CPU.
- **Грабля:** релизный бинарь cuBLAS скомпилён под `ARCHS=520` (sm_52), а 4060 Ti — sm_89 → ядра **JIT-компилируются из PTX через nvrtc при первом инференсе** (~2с). Поэтому `whisper-cli` one-shot медленный (JIT каждый раз), а `whisper-server` — JIT один раз → дальше быстро. ⇒ движок по умолчанию **whisper_server** + **прогрев на старте** (`engine::warmup`: поднять сервер и прогнать тишину).
- `whisper-server` управляется как дочерний процесс (порт 8771), запросы `/inference` через `curl` (multipart, `response_format=text`); гасится при выходе. Фолбэк на `whisper-cli` при сбое.
- **Инсталлятор пока бандлит только CPU-сборку** (мала, универсальна). GPU-сборка (~700 МБ, в осн. `cublasLt` 473 МБ) — локальные resources (dev-путь), для раздачи — отдельный «GPU-пак» (TODO).

## D-016 · «Умная система»: гейт уверенности против галлюцинаций whisper
**Жалоба:** «очень плохое распознавание». **Диагностика по РЕАЛЬНЫМ записям пользователя** (приложение сохраняет их в `dataset/`):
- Длинная чёткая речь (14с, 16с) — распознаётся **идеально**. Захват/ресемпл/уровень звука — в норме (peak 0.84, -22 dBFS, онсет не обрезан).
- Короткие/невнятные фрагменты → **галлюцинации** («Яблоковцы», «Я прокурс», «А пракос»). Это врождённая болезнь whisper на коротком/нечётком звуке, а приложение вставляло этот бред.
**Что НЕ помогло:** fp16 vs q5, beam search, `--suppress-nst` (через сервер без эффекта). Праймящий prompt и «словарь частых слов» в `initial_prompt` — **ухудшали** (prime подавлял даже хорошие записи).
**Решение (verbose_json + гейт уверенности):** запрашиваем `response_format=verbose_json`, парсим (serde_json) пословные `probability`, `no_speech_prob`, `detected_language`. Отклоняем вставку, если: mean(word prob) < 0.60, ИЛИ доля слов с prob<0.4 > 0.34, ИЛИ no_speech_prob > 0.70, ИЛИ детектирован НЕ русский с prob>0.6. При отклонении — НЕ вставляем мусор, играем звук ошибки + событие `norecog` («не расслышал»).
**Данные-подтверждение:** мусор — mean 0.57–0.605 (одно whisper детектил как ФРАНЦУЗСКИЙ 0.92); хорошая речь — mean ~0.9, ru 0.999. Гейт чисто разделяет.
**Также:** убран адаптивный word-salad prompt и дефолтный prime; biasing — только пользовательский словарь.

## D-017 · ИИ-слой: стиль-под-приложение + обучение на исправлениях (Google Gemini, BYOK)
По запросу пользователя. Затронуты gemini.rs, app_context.rs, фронтенд.
- **Движок:** Google **Gemini** (Google AI Studio, BYOK, бесплатный лимит). Ключ хранится локально, шлётся в заголовке `x-goog-api-key` (НЕ в URL). Запросы — через `curl` (без reqwest). Модель по умолчанию `gemini-2.5-flash`. **Ключ заводит пользователь** на aistudio.google.com/apikey.
- **Стиль по приложению** (`tone_by_app`): `app_context::detect()` — активное окно (exe + заголовок) через winapi FFI → категория: `formal` (Gmail/Outlook/Word), `casual` (Telegram/WhatsApp/Instagram/Discord/VK), `ai` (ChatGPT/Claude/Gemini/Perplexity…), иначе `neutral`. Gemini `refine()` переписывает текст в стиле категории (для `neutral` LLM НЕ вызывается — без задержки/затрат).
- **Облачный ASR** (`cloud_asr`, опц.): Gemini `transcribe()` (аудио inline base64) как альтернатива локальному whisper. По умолчанию выкл (whisper приватнее/быстрее на GPU).
- **Обучение на исправлениях:** таблица `corrections`; применяются в постобработке (`apply_corrections`). **Авто-захват:** монитор буфера обмена — если пользователь скопировал отредактированную версию последней вставки (Jaccard 0.5–1.0, равная длина), учим пословные замены (распознано→правильно). Плюс ручной ввод в UI. Известные исправления также передаются Gemini в инструкции рерайта.
- **Pluggable:** `ai_backend` off|gemini; работает только при включённом ИИ и не-verbatim. Без ключа всё деградирует к локальному whisper + правилам.

## D-018 · Живой стрим текста в плашке + режим вставки Всегда/Авто/Никогда (чанковый псевдо-стрим)
По запросу пользователя (паритет с Aqua/Wispr — главная визуальная фича брифа). Этапы: design-lock → backend‖frontend → adversarial verify.
- **Выбор движка (сверено вебом, июнь 2026):** истинного потокового STT для русского в готовом виде НЕТ. whisper-server не имеет стримингового эндпоинта; sherpa-onnx online-моделей для русского нет (offline-only, issue #2435); Parakeet TDT v3 НЕ cache-aware (NVIDIA шлёт к FastConformer-стрим без русского) — все пути сводятся к чанкам. ⇒ **переиспользуем GPU whisper-server чанками**, без новых зависимостей/моделей (анти-оверинжиниринг).
- **Как:** во время записи фоновый поток `partial_loop` каждые ~700мс снимает накопленный буфер (`Capture::buffer_handle()` — клон Arc, НЕ сливает), ресемплит, пишет `tmp/partial.wav` (ASCII, R5), гонит `asr::transcribe_server_partial` (**без гейта** — показываем даже неуверенное) → событие `partial {text}` → плашка рисует текст серым. Замерено на GPU: партиал 0.33–0.74с (≪ каденса 700мс для нормальной речи).
- **Сериализация:** один whisper-server/порт → общий `asr_lock` (тики через `try_lock` пропускают тик, если занят; финал блокирующе). На стопе петля останавливается флагом и **джойнится** до финала. Финальный проход — с гейтом уверенности (как раньше), мусор в чужое окно не улетает.
- **Режим вставки `stream_mode` ∈ {never|auto|always}, дефолт `auto`:** плашка стримит ВСЕГДА (когда движок `whisper_server`); вставка в поле — по режиму. `never` — только финал чистовиком (как было); `always` — каждый партиал клавишами через `inject_incremental` (общий char-префикс → backspace+дозапись, корректно для кириллицы); `auto` — печатаем лишь СТАБИЛЬНЫЙ токен-префикс (совпавший в двух последних партиалах), волатильный хвост — только в плашке. Живая вставка — ТОЛЬКО клавишами (не clipboard: paste не умеет backspace).
- **Защита:** при смене активного окна (отпечаток exe+title через `app_context::detect`) живая вставка глушится до конца диктовки (`abort`) — не печатаем в чужое поле. При отклонении финала гейтом, если уже напечатали партиал, экран НЕ стираем.
- **CPU-фолбэк:** при `engine != whisper_server` петля НЕ запускается (партиалы на CPU ~15с — неюзабельно) → плашка показывает статичное «Слушаю…», вставка только финалом.
- **`inject_lock` (фикс гонки, найден adversarial-ревью):** ВСЯ эмиссия клавиш (живые вставки + финальная реконсиляция + обычная вставка) под общим мьютексом — иначе при быстром рестарте (латч/двойной тап ≤450мс) detached-поток финала прошлой диктовки и новый партиал-цикл печатали бы вперемешку, портя текст.
- **Файлы:** `engine.rs` (петля, координация, режимы), `audio.rs` (`buffer_handle`), `asr.rs` (`transcribe_server_partial` ungated + `extract_text`), `inject.rs` (`inject_incremental`), `settings.rs`+`types.ts` (`stream_mode`), `Overlay.tsx`+`styles.css` (живой текст, пилюля до 520px), `Recognition.tsx` (селектор режима), `lib.rs` (overlay-окно 560px), `main.rs`/`lib.rs` (`--stream-selftest <wav>` — headless замер каденса/латентности).

## D-023 — GigaAM-v3 как основной русский ASR + production-ready пакет (2026-06-10)

**Решение.** Русский пайплайн переведён с whisper на **GigaAM-v3 e2e RNNT int8** (SberDevices, MIT,
HF istupakov/gigaam-v3-onnx, 4 файла ~216 МБ) через крейт **ort 2.0.0-rc.12** (статическая линковка
prebuilt onnxruntime, БЕЗ cmake — единственный вариант на этой машине). e2e-чекпойнт даёт пунктуацию,
капитализацию и ITN из коробки → LLM-рефайн для «просто нормального текста» не нужен.
Замер (release, CPU): 2с фразы → 60 мс, 16с → 344 мс, против 0.36с на GPU whisper-server и 1.6–2.7с Groq.

**Сопутствующее.**
- `gigaam.rs`: фронтенд log-mel64 повторяет onnx_asr бит-в-бит (DFT-320 таблицами, bf16-округление
  окна/мел-банка), greedy transducer с кэшем dec_out. Грабля: `ort::Error<R>` не Send+Sync → адаптер `.oc()`.
- `vad.rs`: Silero VAD v6 (ресурс resources/vad, 2.3 МБ, вшит в инсталлятор). Два резидентных инстанса:
  стриминговый (петля партиалов) и финальный — общий ломал бы state при rapid-fire.
- Партиалы без GPU: сегментная схема (пауза ≥600мс или 25с закрывают сегмент → committed монотонен
  по построению; тишина не распознаётся вообще). PrefixStabilizer остался только для whisper-пути.
- Длинное аудио: финал режется по VAD-паузам на куски ≤25с (лимит pos_emb модели).
- `inject.rs`: воркер + FIFO-очередь (порядок гарантирован каналом), is_busy() глушит clipboard_monitor.
  Дефолт paste_method=clipboard (печать "type" длинного текста = старое «зависание»).
- `db.rs`: WAL + busy_timeout + авто-восстановление при malformed (у пользователя БД была битая —
  приложение не стартовало; настройки восстановлены из сырых байтов).
- Orb-оверлей по спеке Aqua Voice (снята из app.asar): окно ужимается под пилюлю (overlay_box),
  НЕ click-through, drag + память позиции (kv overlay_pos), событие level (RMS 33мс) для баров.
- Темы system/light/dark (data-theme, localStorage vf-theme до рендера).
- Дефолты: stt_provider=local, engine=gigaam, язык ru; облачные пресеты (Groq и др.) остались опцией,
  ключ пользователя сохранён. en → whisper (GPU server / cli), Parakeet отвергнут (+650МБ, слабый русский).
- Инсталлятор 0.2.0 (Inno): + resources/vad; модели GigaAM качаются при первом запуске автоматически
  (models.rs ensure_default_models, суммарный прогресс, докачка), вшивать 216 МБ в setup не стали.

## D-024 — Потеря надиктованного текста: политика самоисправлений и гард рерайта (2026-07-25)

**Причина.** Пользователь получал в поле НЕ то, что сказал: из текста молча пропадали куски,
иногда половина предложения. Диагностика нашла пять независимых мест потери.

1. **Локальные «самоисправления» резали обычную речь.** В `SELF_CORRECTION_MARKERS`
   (`postprocess.rs`) лежали обычные связки русского языка: `то есть`, `в смысле`, `нет`,
   `ой`, `точнее`, `вернее`, `не так`. Любое их появление вырезало левую часть фразы,
   а `correction_cut_point` при отсутствии якорного слова безусловно сносил до 4 слов
   (и мог снести всё начало). Правило работало ВСЕГДА, даже при `ai_backend = "off"` —
   пользователь винил ИИ, а резал локальный regex-слой.
   «Это стоит сто рублей, то есть примерно один доллар» → «Это примерно один доллар».
2. **Окно Ollama (4096) было меньше системного промпта** (~21 КБ ≈ 6k токенов):
   промпт молча срезался, на генерацию места не оставалось, `num_predict` не задан.
3. **Лимиты вывода и обрыв ответа не проверялись.** `rewrite.rs` слал жёсткие
   `max_tokens = 1200`; ни один из трёх клиентов не смотрел `finish_reason` /
   `finishReason` / `done_reason` — обрубок вставлялся как готовый текст.
   Gemini 2.5 Flash дополнительно тратил бюджет вывода на thinking.
4. **Гард `rewrite_is_grounded` убивал весь полезный рерайт.** Он требовал совпадения
   содержательных токенов 1-в-1 И ПО ПОРЯДКУ: любое исправление окончания, склейка с уже
   набранным текстом, нормальная переформулировка — всё отклонялось, и в поле уходил сырой
   текст. Это и выглядело как «модель не понимает смысл». При этом гард обходился при
   `force: true` и вовсе не применялся в `commands.rs`.
5. **`[ОКРУЖЕНИЕ]` содержало саму диктовку.** В live-режиме черновик уже напечатан в поле,
   а `rewrite_context_hint` про флаг `live_inserted` не знал → модель видела один и тот же
   текст дважды и схлопывала дубль, съедая начало.

**Решение.**
- Маркеры самоисправления разделены на три класса: `Cancel` (только явные отмены —
  «нет, стоп», «стоп, не то», «отмена», «забудь», «зачеркни») режет как раньше;
  `Replacement` («точнее», «вернее», «нет», «ой», «не так», «погоди») срабатывает только
  при якорном слове или ровно одном слове справа; `Reformulation` («то есть», «в смысле») —
  только при якоре. Без якоря рез ограничен одним фрагментом и никогда не сносит начало фразы.
  Старое поведение доступно опцией `aggressive_self_correction` (по умолчанию **выкл**).
- Филлеры: добавлен список зависимых продолжений (`FILLER_DEPENDENTS`) — «как бы то ни было»,
  «в общем виде», «короче говоря», «типа того», «это самое главное» больше не режутся.
  «значит» убрано из контекстных филлеров: как союз-следствие оно содержательно, а отличить
  его от пустой вводной по тексту нельзя.
- Системный промпт (`voiceflow_ru.txt`, ШАГ 3) и инструкция Gemini переписаны: список триггеров
  Backtrack сокращён до команд отмены, добавлен явный запрет удалять содержательное при сомнении.
- Ollama: `num_ctx` и `num_predict` считаются от фактической длины (минимум 16384),
  `done_reason = "length"` → ошибка → fallback.
- Лимит вывода везде считается от длины входа (`net::output_token_budget`), верхняя граница —
  настройка `rewrite_max_output_tokens`. Все три клиента проверяют признак обрыва.
  Для Gemini задан `maxOutputTokens` и `thinkingConfig.thinkingBudget = 0`.
- `rewrite_is_grounded` заменён на **асимметричную защиту от потери содержания**: recall по
  основам слов (обрезка до 4 символов, числа целиком) ≥ `rewrite_min_recall` (по умолчанию 0.9).
  Переформулировка, смена порядка слов и исправление морфологии разрешены; проверка на
  раздувание вдвое сохранена. При отклонении логируются ИМЕННО пропавшие слова.
  Гард применяется и на пути `force: true`, и в `commands.rs`; для намеренно сокращающих
  преобразований («Сократить», «в промпт») порог recall = 0.
- `rewrite_context_hint` получил `live_inserted` и вычитает вставленный черновик через уже
  существующий `visible_previous_context_tail`. Окружение обрезается с сохранением ХВОСТА
  (`compact_context_tail`), а не головы.
- Таймаут ИИ вынесен в настройку `ai_timeout_s` (по умолчанию 20 с); локальная модель получает
  минимум 60 с. Фиксированные 10 с означали, что qwen3:4b на CPU не успевал никогда.
- В местах потери речи ДО постобработки (`compact_speech_for_final_asr`, `local_transcribe_long`,
  `trim_silence`) добавлено диагностическое логирование. Параметры VAD не менялись.

**Осознанные последствия.**
- Гард больше НЕ ловит семантическую инверсию добавлением слова («отправь файл» → «отправь без
  файла») и не запрещает смену порядка слов: это цена за возможность вообще применять рерайт.
  Потерю содержания он ловит по-прежнему.
- «Улучшить выделенное» (`force`) теперь тоже проходит проверку recall. Экзотическая
  smart-инструкция вида «переведи на английский» будет отклонена — порог настраиваемый (0 = выкл).

## D-025 — Плашка ≠ вставка, раздел «Промпты», мерилка распознавания (2026-08-06)

**Причина.** Три запроса пользователя одним заходом: (1) кружок иногда показывает не то, что
в итоге вставляется, (2) нужен раздел для промптов, (3) нужно улучшить распознавание.

### 1. Живой черновик пропускал шаг определения языка

Финальный auto-маршрут делает LID: Parakeet-черновик → `parakeet::is_mostly_cyrillic` →
кириллица уходит в GigaAM, всё остальное — в whisper (`engine.rs`, документировано в
`--lid-selftest`). Живой preview этот шаг пропускал: `maybe_start_partial_loop` в двух ветках
(`language = auto` + `engine = gigaam`; macOS `whisper_server` + ru/auto) поднимал GigaAM с
`fixed_lang: Some("ru")` ради каденса. GigaAM — русский ASR, английская и смешанная речь
превращалась в плашке в мусор, а в поле приезжал верный текст от другого движка. Симптом
«кружок врёт» = ровно это расхождение маршрутов, постобработка тут ни при чём
(`clean_live_text` зовёт тот же `process_dictation_text`, что и финал).

**Решение.** `LocalLoopTuning` получил флаг `speculative` — «preview идёт НЕ тем движком, что
финал». Такой маршрут пропускает через `preview_text_trusted` то же правило доверия, которым
финал решает, верить ли GigaAM (`gigaam_auto_final_trusted`): не-кириллический сегмент в плашку
не попадает вовсе. Маршруты, где движок preview совпадает с финальным (явный `ru` → GigaAM,
явный `en` → Parakeet), помечены `speculative: false` и отдают текст как раньше.

**Осознанное последствие.** На английской речи при `language = auto` плашка во время диктовки
остаётся пустой (текст появляется финальным preview после отпускания) — вместо кириллического
мусора. Показать английский текст живьём нельзя: petля типизирована одним движком, а whisper
auto на macOS слишком медленный для тиков (D-018).

**Что НЕ сделано и почему.** Гейт уверенности для GigaAM/Parakeet (joint-логиты и argmax уже
считаются, средняя вероятность токена достаётся почти даром) отложен: порог нечем выбрать, пока
нет замеров, а D-016 — ровно история о том, как параметры ASR крутили вслепую и стало хуже.
Задача переехала в пункт 3, после первого прогона бенча.

### 2. Раздел «Промпты»

Механика уже существовала целиком и была размазана: `app_context` детектит AI-чаты в профиль
`"ai"`, `effective_smart_instruction_for_app` подмешивает подводку «это поле нейросети»,
`ai_prompt_rules` хранит правила по приложениям, rewrite-конвейер с фолбэками готов. Не хватало
двух вещей: правил ПОД КОНКРЕТНУЮ модель (у Claude и GPT они разные) и места, где это видно.

**Решение.**
- `app_context::ai_target` — по тем же маркерам, что и профиль `"ai"`, возвращает конкретную
  модель (`claude`, `chatgpt`, `codex`, `gemini`, `perplexity`, …). Отдельного детекта не заводили.
- `engine::builtin_prompt_rules` — статическая таблица правил оформления по вендорам. Данные
  справочные, поэтому живут в Rust, а не в настройках.
- Настройка `prompt_rebuild` (по умолчанию **выкл**). Включённая считается таким же явным
  opt-in на синхронный рерайт, как своё правило: режим ждёт ответ LLM перед вставкой. Выключенная
  не меняет ничего — тест `builtin_ai_context_does_not_block_final_insert_on_rewrite` держит
  прежнюю гарантию мгновенной вставки для встроенного AI-профиля.
- Вкладка «Промпты» (`sections/Prompts.tsx`): выключатель и переопределения по моделям. Свой
  текст перекрывает встроенный целиком (иначе в инструкцию уехали бы обе версии), пустое поле
  возвращает встроенные правила. Переопределения пишутся в существующий `ai_prompt_rules` —
  новое хранилище и миграция не понадобились.
- Лимит раздувания ответа вынесен из `rewrite_grounding` в параметр: обычный рерайт —
  `REWRITE_MAX_EXPANSION = 2`, поле нейросети — `PROMPT_REBUILD_MAX_EXPANSION = 4`. Структурный
  промпт («сделай кнопку красной» → задача + требования + формат) под 2× не влезает физически.
  Проверка на потерю содержания (recall) при этом НЕ ослаблена.

**Граница.** Пересборка работает в чатах нейросетей. В Cursor, VS Code и терминалах окно
классифицируется как `verbatim`, рерайт там не запускается — отличить чат-панель от редактора
кода по exe и заголовку нельзя, а дословность в коде важнее.

### 3. Мерилка вместо угадайки

D-016 уже фиксировал: beam search, `--suppress-nst` и праймящий prompt распознавание **ухудшали**.
Поэтому сначала инструмент замера, потом параметры.

**Решение.** `voxflow --wer-bench [каталог] [сколько файлов]` рядом с существующими
`--selftest` / `--gigaam-selftest` / `--parakeet-selftest` / `--lid-selftest`. Гоняет записи по
всем доступным маршрутам (GigaAM, Parakeet, whisper-cli, whisper+постобработка отдельной
строкой) и печатает пословный WER на маршрут.

Эталон — файл `<имя>.txt` рядом с `<имя>.wav`. Столбец `samples.text` эталоном служить НЕ может:
там лежит вывод самого ASR, сравнение с ним всегда даёт ноль ошибок. Без эталонов бенч печатает
расхождение маршрутов между собой — этого хватает, чтобы увидеть выпадающий маршрут и написать
эталоны только для спорных записей. По умолчанию берутся 40 последних файлов из `dataset/`
(там сотни записей, полный прогон на три маршрута — часы); сколько взято и сколько пропущено,
печатается в шапке.

**Кандидаты на правку — только после замеров, каждый принимается по цифрам:**
- `asr.rs` — путь `whisper-cli` идёт чистой жадностью (нет ни `-bs`, ни `-bo`), тогда как сервер
  поднимается с `-bs 2 -bo 2`. Расхождение движков финала между собой.
- `-nf` (отключение temperature fallback) стоит и в cli, и в сервере — whisper не может
  переспросить сложный сегмент. В списке проверенного в D-016 этого пункта нет.
- Гейт уверенности для GigaAM/Parakeet (см. пункт 1).
- `compact_speech_for_final_asr`: `SPEECH_PROB = 0.35`, внутренние речевые островки склеиваются
  без padding — подозреваемый в срезании тихих краёв слов.

Что не улучшило — записывать сюда строкой, чтобы не проверять это в третий раз.

## D-026 — Правила промпта под конкретную модель и подхват обновлений документации (2026-08-06)

**Причина.** Пользователь: раздел «Промпты» должен различать не семейство, а **номер** модели —
у Opus и Sonnet правила разные, — брать их из документации вендора и подхватывать её изменения
автоматически, без обновления приложения.

**Проверка перед проектированием (важно, она изменила решение).** Определить номер модели
автоматически **нечем**:

- заголовок окна приложения Claude — буквально `Claude`, без модели и без названия чата;
- `entire contents` окна через System Events отдаёт **0 элементов**: Electron дерево доступности
  наружу не публикует;
- VoxFlow видит только exe, заголовок и текст СФОКУСИРОВАННОГО поля (`focused_field_inner`) —
  ни в одном из трёх номера модели нет.

Поэтому сервис (Claude / ChatGPT / Gemini) определяется автоматически, как и раньше, а номер
модели выбирается пользователем в разделе. Попытка «угадать» модель дала бы правила не той
модели — хуже, чем честный выпадающий список.

**Решение.**
- Правила стали ДАННЫМИ: `src-tauri/src/prompt_rules.json` (вшит через `include_str!`) —
  каталог моделей с `id`, сервисом, ссылкой на страницу документации и текстом правил.
  Rust-таблица не годилась: каждое изменение документации требовало бы новой сборки.
- Настройка `prompt_models` — какая модель выбрана внутри сервиса. Нет выбора → первая модель
  сервиса; сервиса нет в каталоге (Grok, DeepSeek, Copilot) → запись `generic`; выбор указывает
  на исчезнувшую модель → откат к сервису, а не молчаливое выключение пересборки.
- **Подхват обновлений.** Anthropic отдаёт страницы промптинга чистым markdown (`.md`,
  проверено: 200 и 11–16 КБ), поэтому HTML парсить не нужно. Фоновый проход скачивает документ,
  считает SHA-256 и сравнивает с хешем прошлой пересборки. Хеш совпал — работы нет, двигается
  только отметка времени. Изменился — документ уходит в настроенный пользователем бэкенд, тот
  выжимает короткий список правил, результат ложится в
  `data_dir/prompt_rules_cache.json` вместе с новым хешем. Правила из кэша перекрывают вшитые.
- Проход запускается на старте, только когда `prompt_rebuild` включён, и не чаще раза в сутки:
  он тратит чужие токены и ходит в сеть, поэтому не должен работать у тех, кто функцией не
  пользуется. Без настроенного бэкенда выходит СРАЗУ, не трогая сеть — качать документ, который
  нечем обработать, бессмысленно.
- Выжимка проверяется на правдоподобие (80–900 символов). Слишком короткий ответ — модель не
  справилась, слишком длинный — пересказала документацию. И то и другое хуже базовых правил,
  поэтому такой результат отклоняется с записью в лог, а не принимается молча.
- `engine::ask_configured_llm` — разовый запрос к уже настроенному бэкенду через тот же
  `configured_rewrite_backend`. Без него пересборка звала бы `rewrite::refine` напрямую, а это
  ТОЛЬКО OpenAI-совместимый маршрут: у пользователей Gemini и Ollama выжимка не работала бы
  никогда.

**Границы честности.** Приложение подхватывает изменение САМОГО ДОКУМЕНТА по известному URL. Оно
не узнаёт о модели, страницы которой ещё нет в каталоге, — такая приезжает с обновлением
приложения. В интерфейсе видно, из чего сейчас взяты правила и когда документацию проверяли.

**Источники базовых правил** (по ним составлен `prompt_rules.json`): страницы промптинга
Claude Opus 5 и Claude Sonnet 5 на platform.claude.com, руководства GPT-5.1/5.2 и Codex на
developers.openai.com, руководство Gemini 3 на ai.google.dev. Из песочницы этой сессии
проверялись только адреса Anthropic; остальные — по поисковой выдаче вендорских доменов.

## D-028 — Автоопределение локального ИИ и подбор моделей под машину (2026-08-06)

**Причина.** Локальный бэкенд подключался только руками: выбрать движок, вписать адрес, выбрать
модель, а если модели нет — идти в терминал за `ollama pull` (`Ai.tsx`, `commands.rs`). Человек
с уже установленной Ollama об этом не узнавал вовсе. Запрос: приложение само находит локальный
ИИ, само предлагает его включить, модели ставятся кнопкой. Уточнено: ловим **Ollama и
LM Studio**, ряд моделей **подстраивается под любой компьютер**.

**Решение.**
- `local_ai.rs` — проба локальных портов: Ollama `:11434/api/tags`, LM Studio `:1234/v1/models`,
  llama.cpp `:8080/v1/models`. Наружу не ходит, только петля. Порт 8771 занят собственным
  whisper-server и не пересекается.
- **LM Studio и llama.cpp отдельного бэкенда не получили.** Оба говорят OpenAI-совместимым
  протоколом, который уже реализован в `rewrite.rs`: находим — заполняем `rewrite_base_url` /
  `rewrite_model` и включаем `openai_compat`.
- **Ряд моделей считается от объёма памяти машины,** а не прибит к одной конфигурации. Каталог
  размечен ярусами (`min_ram_gb`), показываются три самые крупные подходящие: на 8 ГБ — только
  `qwen2.5:3b`, на 16 ГБ — четырёхмиллиардные, на 32 ГБ ряд сдвигается к 8B и 12B. Не влезающие
  **не прячем**, а показываем с пометкой, сколько памяти им нужно.
- Пороги берутся от **полного** объёма памяти, а не от свободного в момент запуска: свободное
  скачет от того, открыт ли браузер, и выбранная по нему модель назавтра не влезет. Порог заметно
  выше веса модели, потому что рядом живёт распознавание (whisper ~0.5 ГБ, GigaAM и Parakeet
  ~0.65 ГБ каждая). Объём памяти: `sysctl hw.memsize` на macOS, `GlobalMemoryStatusEx` из уже
  подключённого крейта `windows`. Новой зависимости ради двух вызовов не заводили.
- Скачивание — `ollama::pull` через `POST /api/pull` со стриминговым NDJSON; `completed`/`total`
  транслируются в существующие события `model:progress` / `model:done` / `model:error`, поэтому
  индикатор в интерфейсе переиспользован целиком. Оборвавшийся поток без подтверждения `success`
  считается **ошибкой**: молча объявить успех при неполной модели нельзя.
- Карточка сверяет имя в событии со своим тегом. Без этого скачивание whisper показывало бы
  прогресс в карточке локального ИИ — события общие.

**Границы, выбранные сознательно.**
- **Настроенный бэкенд не перезаписывается никогда** (`suggest` возвращает `None`, если
  `ai_backend != "off"`). Молча увести диктовку с выбранного облака на локальную модель значило бы
  поменять и качество, и приватность за спиной. Отдельный тест держит эту гарантию.
- Приложение **не включает** найденный движок само — показывает предложение с «Оставить» и
  «Выключить». Отказ ставит `local_ai_dismissed`, и предложение больше не повторяется.
- Чужое ПО за пользователя не ставим: нет движка — плашка честно говорит об этом и даёт ссылку.
- Модели ставятся только через Ollama. Найден LM Studio без Ollama — кнопок скачивания нет,
  вместо них пометка, что модели ставятся в самом LM Studio.
- Команд `local_ai_apply` / `local_ai_dismiss` нет намеренно: это обычная запись настроек, и
  фронт делает её тем же `update`, что и любое другое поле. Второй путь к тем же полям пришлось
  бы держать синхронным с первым.

**Не проверено вживую:** на машине разработчика Ollama не установлена, поэтому проверен только
путь «движок не найден». Ветку с реальным движком, автоопределением и скачиванием надо пройти
после установки Ollama.

### D-028 · уточнение — подбор идёт по КОНФИГУРАЦИИ, а не по одной памяти

Первая версия судила только по объёму ОЗУ. На маке это работает, потому что память общая, но
на десктопе с дискретной картой решает **VRAM**: 16 ГБ видеопамяти тянут то, чего не потянут
16 ГБ системной памяти на Apple Silicon. Судить по одному ОЗУ означало занижать ряд владельцам
нормальных карт.

Введён профиль машины `local_ai::Machine` — объём памяти, число ядер и ускоритель
(`Accel::AppleSilicon` | `Nvidia { vram_gb }` | `CpuOnly`). Правило `fits_machine`:

- **дискретная NVIDIA с известным объёмом** — модель проходит, если `size + 1.5 ГБ ≤ VRAM`;
  системная память при этом ни при чём (контекст и KV-кэш тоже живут в видеопамяти, отсюда запас);
- **общая память** (Apple Silicon) и **карта с неопределившимся объёмом** — по ярусам `min_ram_gb`,
  как раньше; выдумывать число вместо неизвестного нельзя;
- **без ускорителя** — потолок 2.5 ГБ независимо от объёма памяти: на голом процессоре крупная
  модель считает так долго, что вставка текста превращается в ожидание, и предлагать её нечестно.

Ускоритель определяется так: на macOS `sysctl -n hw.optional.arm64` (на Intel-маке общей памяти
нет, поэтому он попадает в `CpuOnly`); на остальных — существующий `paths::has_nvidia()`, а объём
через `nvidia-smi --query-gpu=memory.total` (ставится вместе с драйвером). Несколько карт — берём
самую большую.

Профиль показывается в интерфейсе целиком («16 ГБ памяти, 10 ядер, Apple Silicon, память общая
с GPU»), чтобы человеку было видно, ПОЧЕМУ предложен именно такой ряд.

## D-029 — Плашка врала на длинной фразе: рез сегмента по счётчику (2026-08-07)

**Причина.** Пользователь: «плашка пишет одно слово, а вставляется другое, правильное». D-025
закрыл случай с чужим движком (спекулятивный preview на английской речи), но остался второй,
чисто русский: на фразе длиннее лимита сегмента.

**Что происходило.** `local_partial_loop` закрывает активный сегмент по паузе ≥600 мс **либо по
лимиту длины** (`max_seg_samples` = 8 с). Второе условие срабатывало где придётся — VAD в этот
момент чаще всего посреди слова. Кусок уходил в `committed_segs` **навсегда** (закрытый сегмент
не перераспознаётся), а следующий стартовал с середины того же слова. Финал декодирует запись
целиком и вставлял слово верно — отсюда расхождение.

Замер на своих записях (`dataset/`, GigaAM, старое правило) показывает ровно это: резы ложились
на сетку 8.30 / 16.62 / 24.94 с независимо от речи, и в плашке оставалось
`«…как может быть нап» + «Написано, как может быть…»`, `«Новую версию с исправлен»`,
`«и выложи на гидраб.»`.

**Решение.** Превью резать так же, как это уже делает финал: `local_asr_segmented` при
переполнении unit-а отходит назад до ближайшей тишины, а не режет по счётчику. Теперь то же в
живой петле — `segment_cut_bound`:

- пауза ≥600 мс — как раньше, рез по концу речи + 300 мс хвоста;
- лимит длины — рез по **микропаузе** (провал VAD ≥160 мс), по её середине;
- микропауза засчитывается, только если сегмент к ней уже заполнен на ¾: рез по паузе, найденной
  сильно раньше лимита, оставляет короткий кусок, а короткий кусок ASR читает хуже длинного —
  выгоднее дождаться следующей;
- потолок: +4 с сверх лимита. Речь совсем без пауз режется по-старому, зато стоимость тика
  остаётся ограниченной (тик декодирует активный сегмент целиком и держит замок модели, которого
  ждёт финал).

**Почему именно так, а не иначе (всё замерено, не выбрано на глаз).** Тест
`preview_pill_diverges_less_from_the_final_after_the_micro_pause_cut` гоняет записи двумя
правилами и считает пословное расхождение плашки с финалом. На 18 записях длиннее лимита:

| вариант | расхождение с финалом |
|---|---|
| было (рез по счётчику) | 0.159 |
| рез по любому провалу VAD | 0.112 |
| + порог микропаузы 160 мс | 0.104 (на 7 записях; на 18 — хуже без порога заполнения) |
| рез у левого края паузы | 0.109 — **хуже**: обрезанное начало слова ASR не восстанавливает |
| порог заполнения ½ | 0.127 |
| **порог ¾ (принято)** | **0.119** |
| порог ⅞ | 0.117 — в пределах шума, но чаще упирается в потолок overrun |

**Границы.** Правило меняет только живой черновик; финальный текст и вставка в поле не тронуты.
Расхождение убрано не до нуля и не может быть: превью читает фразу кусками, финал — целиком.
Осталось 4 записи из 18, где стало чуть хуже.

**Не сделано.** `PrefixStabilizer` (whisper-маршрут) фиксирует префикс с гистерезисом и тоже не
переписывает уже показанное — это отдельный класс той же болезни. Не трогали: маршрут другой, а
ослабление гистерезиса вернёт «плашку, которая дёргается» (2.0.13).
